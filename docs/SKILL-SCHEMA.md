# 技能与效果配置

确认日期：2026-11-04。技能是获得、装配和升级的整体；一个技能包含多个效果，每个效果包含监听范围、触发时机、触发条件和触发结果。结果由有顺序的操作组成。没有独立的规则表，也没有延迟生效或选格时机字段。Buff没有等级；完整逐列说明、生命周期和可照填示例见 [Buff配置手册](BUFF-CONFIG.md)。

## 表结构与填写约定

| 表 | 主键与关联 | 字段职责 |
| --- | --- | --- |
| Skill | SkillID唯一 | 名称、说明、图标、技能栏、品质、精英限定、最大等级（当前1—3） |
| SkillEffect | EffectID唯一；SkillID引用技能 | 顺序、监听区域、触发时机、触发主体、回合归属、入场原因、伤害类型、条件BuffID、比较、条件层数、ResultGroupID |
| EffectResult | ResultGroupID＋顺序唯一 | 操作、目标、目标区域、BuffID、层数、等级1—3（技能）、数值（Buff固定结果） |
| Buff | BuffID唯一 | 名称、类型、生效区域、叠加方式、合并范围、最大层数、持续时间、持续回合、离场处理、图标、数值合并、时长刷新、满层处理、护盾补充 |
| BuffEffect | EffectID唯一；BuffID引用Buff | 监听、时机、条件、结果组、移除原因；行为随Buff附着，支持自身生命周期 |

技能不重复维护效果ID列表。效果通过SkillID归属一个技能；一个技能可有任意多行效果。结果组允许被多个效果引用；引用的是定义，运行状态不共享。同一角色两个技能各自包含相似效果时分别触发，不自动去重。技能结果按技能等级取值，Buff结果读取固定数值。

正式工作簿含以上5表及Character、Level、Node、Chapter、Dialogue、DialogueLine，共11表。教学工作簿仅上述5表＋Character、Level，共7表，不依赖章节或节点。物理工作表数量增加没有扩大教学关配置层级。

## 监听、条件和顺序

- 监听区域：battlefield（战场）、bench（备战）、any（两者）。决定持有者在哪里时接收事件。
- 触发时机：unit_enter、unit_leave、turn_start、turn_end、attack_declared、before_damage、damage_taken、healed、unit_defeated、attack_end。
- 触发主体：self（自身）、other_ally（其他友军）；阶段事件只能self，每单位每阶段一条事件。
- 回合归属：own、opponent、any，均相对于持有者所属方。阶段事件会发给双方及备战区，再由监听范围和归属筛选。
- 入场原因：exchange、reinforce、any；仅入场事件可筛选。初始布阵、场上互换、免费备战互换不产生入场事件。
- 伤害类型：combat、skill、health_loss、any；仅受伤事件可筛选。实际生命损失大于0才发受伤事件，完全被护盾吸收不计数。
- 条件：当前支持自身指定Buff总层数与非负整数比较，gte（大于等于）、eq（等于）、lt（小于）。空条件表示无额外条件；不支持任意表达式或脚本。
- 条件在事件触发时检查一次，生成一组结果操作。即使有6层，单次“回合开始，≥3层”的效果也只触发一次。执行移除3层后剩余3层，不自动循环。
- 同技能效果顺序按数值升序执行；同一事件仍遵循现有单位优先级与后入先出堆叠。组内结果按数值升序执行，每个结果后更新状态；新触发在当前结果组完成后继续处理。
- 离场效果保留事件的原位置；在场监听可以接收自身离场。已触发效果不因来源离场自动取消。监听停止不会隐式清除Buff，清除须用结果操作或Buff离场规则。
- passive是现有常驻能力的装配态标记，不是反复触发事件。当前仅支持常驻护甲、通用减伤、敏捷、战斗伤害免疫；随装配和监听区域动态计算，不重复发放Buff。

## 触发结果和目标

操作：apply_buff（获得Buff）、remove_buff（移除指定层数）、heal（治疗）、deal_damage（技能伤害）、swap_positions（己方场上换位）。获得Buff时“层数”填写新增层数，等级数值是每层数值；marker只保存层数，数值填0。移除Buff时等级数值表示移除层数，余量不足移除现有层数，归零删除。攻击Buff允许负数，其他操作数值为非负整数。

目标默认是格子：每个结果执行时根据当前来源位置选格，读取格子当前单位。空格不执行，不追踪触发时的单位。没有选格时机配置。self为明确的单位目标例外；离场后对自身治疗仍作用于原单位，目标区域应填any或bench。

| 目标枚举 | 解释 |
| --- | --- |
| opposing_unit | 历史枚举名保留；语义为敌方正前方格，非锁定单位 |
| front_sides | 敌方正前方格的实际左右邻格，边缘不环绕 |
| lower_ally | 己方循环下一战场格，1→2→3→1，保持已确认旧技能语义 |
| rear_ally / rear_enemy | 自身所在战线对应的己方／敌方备战格，目标区域必须bench |
| all_enemies / all_allies / other_allies | 对应阵营目标区域中的格子；other_allies排除自身 |
| self | 自身单位 |

位置方向使用现有屏幕格位，不增加双方镜像左右或备战横向邻接规则。本期Buff挂载到所选格子的单位并随单位移动；格子自身长期挂载Buff尚未实现。

## Buff规则

- 类型：marker（层数状态）、attack、shield、armor、damage_armor、agile、combat_damage_immunity。
- 叠加只决定层数：add累计至上限；refresh覆盖层数；max取较大层数；independent每次新增独立实例，各自计时。最大层数限制每个实例，不是全部独立实例之和。数值和时长分别由下表控制。
- 合并范围：buff按BuffID合并；source_skill按BuffID＋来源单位＋来源技能合并。不同来源的护盾不会被同技能刷新清掉。
- 护盾余量与层数分开，先减伤再依获得顺序消耗各护盾余量。重复施加如何补充由护盾补充字段控制。护盾耗尽不自动发伤害事件。生命流失绕过护甲和护盾。
- 持续：battle保持本场；turn在当前任意方回合结束移除；owner_turns在承受者所属方回合结束扣减。换入当回合计为第1回合。没有来源方计时选项。
- 离场：keep保留并继续计时；remove离场删除；pause保留，在备战区暂停owner_turns计时。生效区域与计时独立：状态可在备战保留却不发挥属性效果。
- 主角加攻和佣兵护盾保持原例的备战保留；主角时长继续扣减。常驻护甲规则仅场上生效。
- BuffEffect支持普通战斗事件和Buff自身生命周期，包括溢出后的额外结果。驱散标签、一个Buff多个属性修改项、任意条件树、格子Buff及逐层到期仍未实现。不引入完整GAS。

### 独立策略字段

| Buff列 | 可选值 | 准确语义 |
| --- | --- | --- |
| 数值合并 | replace / keep / max / min | 再次施加时覆盖、保留旧值、取数值较大/较小者。作用于整组每层数值；max不是绝对值更强。 |
| 时长刷新 | refresh / keep | owner_turns重新计满或保留剩余回合；首次获得始终初始化。 |
| 满层处理 | apply / reject | 施加前已满层时继续应用其他策略，或整次拒绝（不改层数、数值、时间、护盾）。未满时跨越上限只截断层数。independent总是新建，不合并。 |
| 护盾补充 | reset / add / keep | 补到新容量、追加本次有效新增护盾、保留剩余护盾。任何情况不超过新容量；首次获得始终填满。 |

护盾容量=当前每层数值×当前层数。add模式的追加量=本次数值×实际新增层数；满层追加0，不会偷偷补满。refresh/max模式的追加量=本次数值×本次层数（截到上限）。降低容量会截断旧护盾余量。非护盾类型忽略护盾补充字段。

例：一层攻击+1再加一层+3，数值合并keep得到总+2，replace得到总+6；要分别保留+1和+3，配置independent，得到总+4且分别计时。普通叠层不承诺逐层数值/计时。

兼容：旧表缺列时自动补入旧行为（数值replace，旧max为max；时长refresh、满层apply、护盾reset）。新表已有列却留空或填错枚举会报错。首战护盾明确reset，加攻明确refresh，不改变原设计。

### Buff自带触发效果

BuffEffect通过BuffID归属，不需要在Buff表维护效果ID列表。复用EffectResult，不新增另一套结果操作。可在一个Buff内配置多个效果；属性持续作用仍由Buff类型决定，BuffEffect不能配置passive。

- self、己方回合、选格锚点、条件层数均指Buff持有者；伤害/治疗归因保留原施加者。施加者离场、死亡或卸下技能，不会取消已经附着的Buff。
- 普通战斗事件须同时符合Buff生效区域和效果监听区域；自身生命周期只看效果监听区域。leave=pause仅暂停备战计时。
- Buff没有等级。首次获得保存行为定义、固定values和依赖Buff定义；合并时保留定义，每层属性数值按数值合并策略处理。SkillEffect读取等级列，BuffEffect读取数值列，不继承来源技能等级。
- 一组合并层数每次普通事件只触发一次，结果数值不自动乘层数；独立实例分别触发。普通条件统计同ID总层数；生命周期只通知变化的实例，条件查询本BuffID时读取该实例本次变化快照，其他ID仍读总层数。
- 同单位先按原技能顺序执行技能，再按获得顺序执行Buff，各自效果按顺序列执行；沿用完整结果组后处理新触发的结算规则。阶段事件一次批量收集，新获得Buff不追溯当前已收集事件。
- 移除、到期、离场删除立即停止后续监听；已触发的结果继续完成。离场事件先收集，再执行离场删除，故remove型Buff能触发最后一次离场效果。
- 状态及已触发结果可序列化。实例ID在单位内单调递增；定义以ID依赖图保存，不递归嵌入，支持自引用和互相引用。沿用256项触发链上限，循环会暂停并报错。

中毒例：SkillEffect施加中毒；BuffEffect在持有者己方回合开始→对self造成1伤害。接收者不需要预装中毒技能。回合末扣减持续时间，第三个己方回合末到期后停止触发。

### 自身生命周期

新增buff_added、buff_reapplied、buff_stack_changed、buff_overflow、buff_expired、buff_removed、buff_shield_depleted。仅BuffEffect可用，主体self，回合归属/入场原因/伤害类型any。buff_removed可按移除原因any/expired/dispelled/leave筛选。

首次获得产生added→stack_changed；接受重复施加产生reapplied，层数改变才追加stack_changed；施加前已经满层先产生overflow，reject时只有overflow。跨越上限不属于已满溢出。部分移除只有stack_changed；归零再产生removed；自然到期依次stack_changed→expired→removed。护盾被实际伤害耗尽产生shield_depleted，不删除Buff，补满后可再次触发。

离场删除时持有者已在备战，生命周期监听需any/bench。自然到期与移除都配置结果会分别执行，注意避免重复伤害。到期链在回合交接与胜负裁决前执行。死亡或战斗结束不额外广播移除；不支持按事件实例限定remove_buff，仍按同ID实例获得顺序移除层数。

## 蓄力和首战

通用蓄力例子：受伤→获得1层蓄力；己方回合开始且蓄力≥3→移除3层→伤害前方格。这是可配置组合，不使用延迟队列。

首战保留已确认的七回合节奏，士兵的具体结果仍是加攻后普攻，而不是擅自改为直接技能伤害：

1. SkillEffect：自身受有效伤害，获得1层蓄力。
2. 蓄力的BuffEffect：己方回合结束且蓄力≥3，移除3层，获得1层反击准备。
3. 反击准备的BuffEffect：己方回合开始且反击准备≥1，移除1层，获得攻击＋3、本回合结束移除的强化Buff。

玩家第3回合打出第三次伤害；敌方第3回合仍0攻，末尾转换为反击准备；玩家第4回合可交换，敌方第4回合强化攻击。不存在角色名或关卡ID专用分支。

## 开发实现和兼容

- skill-tables.mjs负责表头、旧格式迁移、所属关系、条件和结果组编译。workbook.mjs统一供发布、配置工坊、对话工坊和教学导入调用。
- 新配置继续编译为现有skills[].rules[]结构，rule.id对应EffectID，effects[]对应结果操作；这是内部兼容表示，不是新增策划规则表。每个结果数值用效果ID＋序号生成参数名。
- buffs.mjs维护可序列化状态、独立策略和生命周期通知；新Buff保存instanceId及有限definitions字典，不保存level。content.mjs校验技能与全部Buff；effects.mjs将变化实例快照接入同一事件收集和结果执行器，job区分source持有者与instigator原施加者；battle.mjs在回合末清理后执行到期链。玩家和AI共享入口。
- 旧Buff存档的levels仅保留兼容读取。旧Excel缺固定数值列时，Buff引用结果的三个等级值一致才自动复制；不一致必须明确填写，不隐式选一级。
- 旧单行Excel可在内存转换；通用工坊导出为新结构。对话工坊只改对白，保留旧技能原表，不隐式改其布局。两份仓库源Excel已显式迁移。
- 旧JSON技能和进行中存档保留兼容；已有旧延迟任务可以执行完，新Excel不再提供每N次触发或延迟字段。新产生的格子技能采用当前占位者语义；历史已入栈的身份快照仅用于完成旧存档任务。
- 非法引用、重复ID、结果序号冲突、未知操作、非法监听、条件缺失和不可用等级必须阻止导入。图标字段为元数据预留，本次未新增资源选择界面。

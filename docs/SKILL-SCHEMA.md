# 技能与效果配置

确认日期：2026-11-04。技能是获得、装配和升级的整体；一个技能包含多个效果，每个效果包含监听范围、触发时机、触发条件和触发结果。结果由有顺序的操作组成。没有独立的规则表，也没有延迟生效或选格时机字段。

## 表结构与填写约定

| 表 | 主键与关联 | 字段职责 |
| --- | --- | --- |
| Skill | SkillID唯一 | 名称、说明、图标、技能栏、品质、精英限定、最大等级（当前1—3） |
| SkillEffect | EffectID唯一；SkillID引用技能 | 顺序、监听区域、触发时机、触发主体、回合归属、入场原因、伤害类型、条件BuffID、比较、条件层数、ResultGroupID |
| EffectResult | ResultGroupID＋顺序唯一 | 操作、目标、目标区域、BuffID、层数、等级1—3 |
| Buff | BuffID唯一 | 名称、类型、生效区域、叠加方式、合并范围、最大层数、持续时间、持续回合、离场处理、图标 |

技能不重复维护效果ID列表。效果通过SkillID归属一个技能；一个技能可有任意多行效果。结果组允许被多个效果引用；引用的是定义，运行状态不共享。同一角色两个技能各自包含相似效果时分别触发，不自动去重。每个结果操作拥有独立的等级数值。

正式工作簿含以上4表及Character、Level、Node、Chapter、Dialogue、DialogueLine，共10表。教学工作簿仅上述4表＋Character、Level，共6表，不依赖章节或节点。物理工作表数量增加没有扩大教学关配置层级。

## 监听、条件和顺序

- 监听区域：battlefield（战场）、bench（备战）、any（两者）。决定持有者在哪里时接收事件。
- 触发时机：unit_enter、unit_leave、turn_start、turn_end、attack_declared、before_damage、damage_taken、healed、unit_defeated、attack_end。
- 触发主体：self（自身）、other_ally（其他友军）；阶段事件只能self，每单位每阶段一条事件。
- 回合归属：own、opponent、any，均相对于持有者所属方。阶段事件会发给双方及备战区，再由监听范围和归属筛选。
- 入场原因：exchange、reinforce、any；仅入场事件可筛选。初始布阵、场上互换、免费备战互换不产生入场事件。
- 伤害类型：combat、skill、health_loss、any；仅受伤事件可筛选。实际生命损失大于0才发受伤事件，完全被护盾吸收不计数。
- 条件：当前支持自身指定Buff总层数与非负整数比较，gte（大于等于）、eq（等于）、lt（小于）。空条件表示无额外条件；不支持任意表达式或脚本。
- 条件在事件触发时检查一次，生成一组结果操作。即使有6层，单次“回合开始，≥3层”的效果也只触发一次。执行移除3层后剩余3层，不自动循环。
- 同技能效果顺序按数值升序执行；同一事件仍遵循现有单位优先级与后入先出堆叠。组内结果按数值升序执行，每个结果后更新状态；新触发在当前结果组完成后继续处理。
- 离场效果保留事件的原位置；在场监听可以接收自身离场。已触发效果不因来源离场自动取消。监听停止不会隐式清除Buff，清除须用结果操作或Buff离场规则。
- passive是现有常驻能力的装配态标记，不是反复触发事件。当前仅支持常驻护甲、通用减伤、敏捷、战斗伤害免疫；随装配和监听区域动态计算，不重复发放Buff。

## 触发结果和目标

操作：apply_buff（获得Buff）、remove_buff（移除指定层数）、heal（治疗）、deal_damage（技能伤害）、swap_positions（己方场上换位）。获得Buff时“层数”填写新增层数，等级数值是每层数值；marker只保存层数，数值填0。移除Buff时等级数值表示移除层数，余量不足移除现有层数，归零删除。攻击Buff允许负数，其他操作数值为非负整数。

目标默认是格子：每个结果执行时根据当前来源位置选格，读取格子当前单位。空格不执行，不追踪触发时的单位。没有选格时机配置。self为明确的单位目标例外；离场后对自身治疗仍作用于原单位，目标区域应填any或bench。

| 目标枚举 | 解释 |
| --- | --- |
| opposing_unit | 历史枚举名保留；语义为敌方正前方格，非锁定单位 |
| front_sides | 敌方正前方格的实际左右邻格，边缘不环绕 |
| lower_ally | 己方循环下一战场格，1→2→3→1，保持已确认旧技能语义 |
| rear_ally / rear_enemy | 自身所在战线对应的己方／敌方备战格，目标区域必须bench |
| all_enemies / all_allies / other_allies | 对应阵营目标区域中的格子；other_allies排除自身 |
| self | 自身单位 |

位置方向使用现有屏幕格位，不增加双方镜像左右或备战横向邻接规则。本期Buff挂载到所选格子的单位并随单位移动；格子自身长期挂载Buff尚未实现。

## Buff规则

- 类型：marker（层数状态）、attack、shield、armor、damage_armor、agile、combat_damage_immunity。
- 叠加：add累计层数至上限；refresh覆盖同组数值／层数并重置时长；max取较大数值和层数并重置时长；independent每次新增独立实例，各自计时。最大层数限制每个实例，不是全部独立实例之和。
- 合并范围：buff按BuffID合并；source_skill按BuffID＋来源单位＋来源技能合并。不同来源的护盾不会被同技能刷新清掉。
- 护盾余量与层数分开，先减伤再依获得顺序消耗各护盾余量。重复施加按叠加规则更新，重设对应实例余量。护盾耗尽不自动发伤害事件。生命流失绕过护甲和护盾。
- 持续：battle保持本场；turn在当前任意方回合结束移除；owner_turns在承受者所属方回合结束扣减。换入当回合计为第1回合。没有来源方计时选项。
- 离场：keep保留并继续计时；remove离场删除；pause保留，在备战区暂停owner_turns计时。生效区域与计时独立：状态可在备战保留却不发挥属性效果。
- 主角加攻和佣兵护盾保持原例的备战保留；主角时长继续扣减。常驻护甲规则仅场上生效。
- 本期没有Buff自身独立监听表、驱散标签、任意条件树或格子Buff。周期行为由技能效果读取Buff层数并执行结果表达。

## 蓄力和首战

通用蓄力例子：受伤→获得1层蓄力；己方回合开始且蓄力≥3→移除3层→伤害前方格。这是可配置组合，不使用延迟队列。

首战保留已确认的七回合节奏，士兵的具体结果仍是加攻后普攻，而不是擅自改为直接技能伤害：

1. 自身受有效伤害：获得1层蓄力。
2. 己方回合结束且蓄力≥3：移除3层，获得1层反击准备。
3. 己方回合开始且反击准备≥1：移除1层，获得攻击＋3、本回合结束移除的强化Buff。

玩家第3回合打出第三次伤害；敌方第3回合仍0攻，末尾转换为反击准备；玩家第4回合可交换，敌方第4回合强化攻击。不存在角色名或关卡ID专用分支。

## 开发实现和兼容

- skill-tables.mjs负责表头、旧格式迁移、所属关系、条件和结果组编译。workbook.mjs统一供发布、配置工坊、对话工坊和教学导入调用。
- 新配置继续编译为现有skills[].rules[]结构，rule.id对应EffectID，effects[]对应结果操作；这是内部兼容表示，不是新增策划规则表。每个结果数值用效果ID＋序号生成参数名。
- buffs.mjs维护可序列化状态及属性、护盾、持续时间。content.mjs统一校验，effects.mjs处理事件与结果，battle.mjs提供阶段事件。玩家和AI共享入口。
- 旧单行Excel可在内存转换；通用工坊导出为新结构。对话工坊只改对白，保留旧技能原表，不隐式改其布局。两份仓库源Excel已显式迁移。
- 旧JSON技能和进行中存档保留兼容；已有旧延迟任务可以执行完，新Excel不再提供每N次触发或延迟字段。新产生的格子技能采用当前占位者语义；历史已入栈的身份快照仅用于完成旧存档任务。
- 非法引用、重复ID、结果序号冲突、未知操作、非法监听、条件缺失和不可用等级必须阻止导入。图标字段为元数据预留，本次未新增资源选择界面。
